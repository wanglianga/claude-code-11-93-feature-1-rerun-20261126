# 环卫线路工作台（封路重排 + 重量差异补证复核）

浏览器端环卫线路工作台，包含两条业务线：

1. **封路重排线**：调度员在地图与路线清单中查看道路限行、服务截止、每站估重、车辆载重与卸载点时段；司机按当前线路登记到站/扫码/称重/满溢/封路；客服按线路版本核查预约通知是否仍有效。
2. **重量差异补证复核线（TRIP-1）**：司机、班组、复核员、站点管理员把一趟清运的重量差异办成可追查的补证案件。缺站点秤票时区分“已核实事实”与“只能待查”，不把估重或整车差额填成站点实收。

全部数据为随题固定的虚构数据，存于浏览器 IndexedDB，可一键重置重放；线路重排在 WebWorker 中计算。

## 技术栈

- React 18 + TypeScript + Vite
- IndexedDB（`idb`）：车辆、站点、路网、封闭、卸载点、通知、线路版本、回执、事件日志全量落库
- WebWorker：重排方案（最小变更 / 全局重排）在后台线程计算
- 纯前端，无后端；nginx 托管静态资源（Docker）

## 随题固定的场景

09:20，清运班组长收到通知：**清河桥（S1—S2）09:20–10:15 封闭**，T1 无法按原顺序进入 S2（S2 截止 10:00；绕行最短 42 分钟，10:02 才到，仍超截止）。

- T1：容量 5.0t、已载 3.0t，剩余 S1（估 0.7t）、S2（估 1.2t）
- T2：容量 4.0t、已载 0.8t，原路线 S3（0.8t）→ S4（0.7t），居民已获知预计到达
- S2 截止 10:00，S3 截止 10:30，S4 截止 11:00；卸载点 D1 开放 08:00–12:00
- 道路限制：市场高架（S2↔S4）限高 2.6m（T1 高 3.1m 不可通行）；车场↔S2 限宽 2.5m

点「生成方案」后页面**并列显示两个方案**（不只给一条最优线）：

- **方案 A · 最小变更**：S2 前置移交 T2，其余已通知顺序不变。T2 = S2→S3→S4，行驶 25 分钟（合计 31）；仅 S2 的 1 条通知需重发
- **方案 B · 全局重排**：T2 = S3→S2→S4，行驶 14 分钟（合计 20，省 11 分钟）；但 S2/S3/S4 共 3 条通知需重发（车辆变更、到达提前 10/7 分钟）

两案均通过吨位、限高限宽、截止时刻、卸载点时段核验；被排除候选（如「T1 承运 S2：绕行 10:02 到达，超过截止 10:00」）一并展示——不用“地图上可达”代替限制核验。

## 关键规则实现

- **估重 ≠ 实称**：规划用估重；称重写入实称后，剩余容量不足必须停收并触发重排；已称重站点重排时按实称计算
- **回执幂等**：同一回执号（或同人同站同动作的同一二维码）重传只计一次，判定“重复”
- **迟到回执冲突**：站点已移交他人或已不在该车当前线路版本中 → 旧回执判定“冲突”，不改变站点状态
- **线路版本**：每次应用方案生成新版本（记录策略、原因、依据版本）；回执、通知均关联版本号，司机端与客服端可追溯到当前线路所依据的版本
- **通知重发判定**：承运车辆变更、到达时刻偏移 >5 分钟、同车相对顺序变化 → 需重发

## 重量差异补证复核（TRIP-1）

### 固定场景

线路依次 **S1、S2、S3**，估重 **0.7 / 1.2 / 0.8 吨**（估重仅对照，永不是实收）。

| 测量 | 标称值 ± 确定性误差 | 区间 |
| --- | --- | --- |
| 出车空载毛重（地磅） | 4.00 ± 0.05 | [3.95, 4.05] |
| 完成三站后终磅（地磅） | 7.60 ± 0.10 | [7.50, 7.70] |
| S1 站点秤票（校准有效） | 0.70 ± 0.05 | [0.65, 0.75] |
| S2 站点秤票（校准有效） | 1.00 ± 0.10 | [0.90, 1.10] |
| S3 | **无站点秤票** | — |

另含出车→S1、S1→S2、S2→终磅 **3 段载荷变动日志 + 班组签认**，样例证明无其他加料、卸料、换车；但“日志存在”不等于“已完成复核”。

### 正式复核边界（选定）：逐站独立核实

逐站只核**本站重量及作业凭证**：S1/S2 凭本站有效秤票先完成独立结论；S3 无有效原件，结论**保留未知并派补证**，不等待跨站材料、**不给量化范围**，更不把估重 0.8t 或整车差额填作 S3 实收。

**对照的联合边界（页面允许查看/签发，但不是两套切换按钮）**：把整趟封闭性与票据组成联合复核单，用「总增重 − 已知站量」推导 S3 候选：

- 总增重（区间减法，误差边界相加）= 终磅 − 空载 = **[3.45, 3.75] 吨**
- 已知 S1+S2 合计 = **[1.55, 1.85] 吨**
- S3 候选 = 总增重 − 已知 = **[1.60, 2.20] 吨**（闭合推导，**不是独立实测**）

联合方式必须先逐项审核 **2 张地磅票 + 3 段封闭签认（共 5 项依赖，比逐站多 5 项工作）**，且候选共同依赖整趟材料。采用该范围前须核全部依赖；任一依赖失效（中途卸料被补发现、离线签认晚到）或终磅更正，已签发联合单自动**重开**。

**终磅更正为 7.80±0.10 后**：总增重变为 [3.65, 3.95]，S3 候选重算为 **[1.80, 2.40] 吨**，并重新打开相应联合复核；而**逐站方式的 S1/S2 票据结论无需撤回**。

### 四个持久化面板（同一案件的不同视角，标签页不是流程切换）

1. **票据修订**：司机提交原票；同票号同内容重传按幂等只计一次、不增量；同票号不同内容判冲突并留痕、不覆盖原票；复核员终磅更正（旧票 superseded 留痕、重开联合）；回站补称重建历史站量被直接拒绝。
2. **站点核实**：逐站独立签发；S1/S2 出实测区间，S3 核为未知并派补证；估重与区间不相容（如 S2 估 1.2t 落在 [0.90,1.10] 外）只记录偏差。
3. **联合候选**：客观材料状态 → 人工逐项勾选 5 依赖 → 齐备后签发；班组补封闭签认、离线晚到失效、中途卸料补发现；未结事项与历史解释只追加。
4. **补证责任**：司机提交补证（可随附有效原件）→ 复核员采用/退回；站点管理员查明缺失原件并按“无原件”结案；底部**正式累计只读取已批准的实测**，估重/差额/推导/重复上传均不计入。

### 验证流程（演示）

1. 用 `reviewer/rev123` 登录，默认在「② 站点核实」：对 **S1、S2** 逐站签发（实测区间 [0.65,0.75]、[0.90,1.10]）；对 **S3** 点签发 → 提示无有效原件、保留未知并派补证，不出量化范围。
2. 切到「③ 联合候选」：直接点签发会被拒（依赖未审齐）；逐项勾选 5 项依赖后签发，S3 候选显示 **[1.60, 2.20]** 并标注“推导非实测”；正式实测累计仍只计已核实站点。
3. 切到「① 票据修订」，用复核员把终磅更正为 **7.80±0.10** → 候选变 **[1.80, 2.40]**、联合单变“已重开”；回到「② 站点核实」确认 **S1/S2 结论未撤回**。
4. 用 `crew/crew123` 登录「③ 联合候选」：勾选“离线签认”后补签 → 该阶段依赖失效；或登记“中途卸料” → 对应签认失效、已签发联合单重开（先在步骤 2 签发后再破坏即可观察重开）。
5. 用 `driver1/drv123` 顶栏切「复核补证」→「④ 补证责任」：随附有效原件（如 1.90±0.10）提交；再用 `reviewer` **采用** → S3 转为独立实测 [1.80,2.00] 并计入正式累计；若不附原件，复核员采用会被拒并退回，`stationadmin/adm123` 可查明缺失原件结案，S3 继续待核且不计重量。
6. 同面板验证：重复上传同票不增量、同号异内容冲突；回站补称被拒；对 S3 发起“差异调查”（估重 0.8t 在候选外）只调查、不重派清运、不改写实收。

### 关键规则实现（复核）

- **实测与推导严格分账**：`recon.ts` 用确定性误差边界做区间加减；推导候选只在联合单签发后单列，永不写入站点实收。
- **封闭性是联合前提**：中途卸料、离线晚到都会令对应签认 `valid=false`，客观依赖立即不成立并自动重开已签发联合单。
- **正式累计口径**：`selectAccumulated` 仅累加“现行有效 + 校准有效 + 站点已核实”的票据标称值；待核站、估重、整车差额、回站补称、重复上传一律不计。
- **终磅更正只影响联合**：旧地磅票留痕、联合重开候选重算；逐站票据结论独立、不撤回。
- **差异调查不重派**：估重与推导/实测不相容仅把补证单置为 `investigating`，不产生新清运、不改写实收。
